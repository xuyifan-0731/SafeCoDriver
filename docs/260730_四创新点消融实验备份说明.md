# 260730 四创新点消融实验备份说明

> 目的：记录四个创新点消融实验的代码位置、实验设计、对比方式、结果表格和后续填表规则。  
> 主实验代码位置：`experiments/innovation_ablation_configs.py`。  
> DeepAccident 入口：`experiments/run_deepaccident_unified_metrics.py --innovation-ablation`。  
> SUMO 入口：`experiments/run_modified_sumo_comparison.py --innovation-ablation`。

## 1. 创新点编码

| 编码 | 创新点 | 当前实现位置 | 对应消融关闭方式 |
|---|---|---|---|
| `V` | 可见性/不确定性风险对象建模与自适应安全边界 | `InnovationHybridBase._get_safety_margin()`、`_without_visibility()` | 不区分 visible / invisible，统一固定安全边界 |
| `D` | 路点修正与风险检测解耦并行 | `InnovationAblationMethod.constrain_waypoints()` | 检测与修正耦合；不触发风险时取消路点修正 |
| `M` | 方向性风险分析，多方向/多对象避障 | `InnovationHybridBase._find_threats()`、`_multi_agent_repulsion()`、`estimate_directional_ttc()` | 只使用最近威胁对象，不做多对象合力与前/后方向拆分 |
| `H` | 长时域可行性检查 | `InnovationHybridBase._find_threats()`、SUMO 中 `apply_rear_escape_lane()` | 只检查近端 3 个路点；SUMO 横向逃逸不做 25m clearance 检查 |

说明：`H` 在当前最优方案中主要体现在“对未来路点持续检查”和“后车压力下横向逃逸前检查相邻车道 clearance”。为了做严格消融，新增了 `lane_escape_unchecked` 和 `apply_rear_escape_lane_unchecked()`，用于模拟没有长时域可行性检查的短视横向避障。

## 4. 对比方式

### 4.1 单点消融

每个单点创新都按以下逻辑比较：

```text
外部对比方法
+ Innov-NONE
+ 单点方法 Innov-X
+ 四点全量 Innov-V+D+M+H
+ 旧主线最优 Hybrid+AND+TTC+RearEscape-thr0.30
```

判断重点：

- DeepAccident：优先看 `WPC%`、`FA(f)`、`Det(s)` 和综合 rank。
- SUMO：优先看 combined `CollRate`、`OverlapRate`、`AvgSev`、`WPC%`。
- 若 `Innov-X > Innov-NONE`，说明该创新点单独有效。
- 若 `Innov-V+D+M+H > Innov-X > Innov-NONE`，说明单点有效且全量组合进一步增强。

### 4.2 两两组合消融

每个两两组合按以下逻辑比较：

```text
外部对比方法
+ Innov-NONE
+ 两个对应单点 Innov-X / Innov-Y
+ 两两组合 Innov-X+Y
+ 四点全量 Innov-V+D+M+H
+ 旧主线最优 Hybrid+AND+TTC+RearEscape-thr0.30
```

判断重点：

- 若 `Innov-X+Y` 已经优于外部强对比方法，并且 `Innov-V+D+M+H` 继续优于 `Innov-X+Y`，则具备拆成两篇论文的可能。
- 若所有两两组合都不明显优于外部对比方法，且只有四点全量明显最优，则不建议拆分，应把四个点放在一篇论文中。
- 若某个两点组合只在 DeepAccident 有优势、SUMO 不稳定，则它更适合作为离线路点安全论文，不适合单独宣称闭环安全。
- 若某个两点组合在 SUMO 明显降低碰撞率，但 DeepAccident 排名一般，则它更适合作为闭环安全/后向压力论文。

## 7. 后续填表规则

每跑完一个结果目录，就按以下顺序回填：

1. DeepAccident 先填 `DA WPC`、`DA FA(f)`、`DA Det(s)`、`DA Rank`。
2. SUMO 三组都跑完后，合并 `base/stress/random-stress` 的 `per_run.csv`，填 `SUMO CollRate`、`SUMO OverlapRate`、`SUMO AvgSev`、`SUMO WPC`。
3. 如果只跑完单个 SUMO 子集，在表格备注里标明 `base only`、`stress only` 或 `random-stress only`，不要当作最终 combined 结论。
4. 拆分论文判断只使用完整 DeepAccident + SUMO combined 结果，不使用 smoke 或单场景结果。

辅助汇总脚本：

```bash
/raid/xuyifan/miniconda3/envs/coop-safety/bin/python \
  scripts/summarize_innovation_ablation.py \
  --deepaccident-dir results/260730_innovation_ablation_deepaccident_full \
  --sumo-dirs \
    results/260730_innovation_ablation_sumo_base_smoke \
    results/260730_innovation_ablation_sumo_stress \
    results/260730_innovation_ablation_sumo_random_stress \
  --out results/260730_innovation_ablation_summary_combined.csv
```

如果只跑完 SUMO base，可以临时把 `--sumo-dirs` 改成：

```bash
--sumo-dirs results/260730_innovation_ablation_sumo_base_smoke
```

但此时 `SUMO_runs` 只有 base 场景数量，结论栏必须标注 `base only`。

### 8.2 拆分论文建议

当前结果支持“弱拆分”，不支持“严格四点全量在所有指标上都大于两点组合”的强拆分叙事。

可行拆法：

1. **论文 A：闭环避障与后向压力安全**
   - 主创新点：`M+H`，即方向性/多对象风险分析 + 长时域可行性检查。
   - 证据：SUMO combined 最优，`CollRate=0.115385`、`OverlapRate=0.115385`、`WPC=0`；明显优于 `Innov-NONE`、`D`、`D+M` 等。
   - 风险：DeepAccident `FA(f)=0.6451` 偏高，因此这篇更适合强调闭环场景和 SUMO stress/random-stress，不宜主打低误报。

2. **论文 B：完整协同安全约束系统**
   - 主创新点：`V+D+M+H`，在 `M+H` 闭环安全基础上加入可见性建模和检测/修正解耦。
   - 证据：保持 `M+H` 的最低 SUMO 碰撞率，同时把 DeepAccident `FA(f)` 从 `0.6451` 降到 `0.4840`。
   - 表述重点：不是“所有指标进一步降低”，而是“保持闭环安全的同时显著降低离线误报、形成完整可解释系统”。

不建议的拆法：

- 不建议把 `V` 单独作为一篇核心创新，当前单点提升不稳定。
- 不建议把 `D+H` 单独写成闭环安全论文；它 DeepAccident 排名第 2，但 SUMO combined `CollRate=0.269231`，闭环表现不够好。
- 不建议用 `D+M` 作为主组合；它误报低，但 SUMO `CollRate=0.346154`、`WPC=0.025398`，安全性不足。
