## 2. 最终方法结构

最终方法由同一个 V1 detector checkpoint 加上可解释的几何/TTC/后车逃逸控制组成，方法入口在 `experiments/final_method_configs.py:48`：

```text
Hybrid+AND+TTC+RearEscape-thr0.30
= V1 碰撞概率阈值 0.30
+ 可见性自适应几何路点修正
+ V1 与几何威胁 AND 融合
+ 前/侧向 TTC 强制触发
+ 后车压力感知速度保持与横向逃逸标记
```

核心判定公式在 `experiments/method_variants.py:224` 到 `experiments/method_variants.py:252`：

```text
front_ttc, rear_ttc = directional_ttc(perception)
rear_gap = nearest_rear_gap(perception)

fire = (P_v1 > 0.30 and n_geom > 0) or (front_ttc < 3.0)
close_rear = rear_gap < 18.0 or rear_ttc < 2.5

if close_rear and front_ttc >= 1.0:
    lane_escape = 1
    target_speed_factor = 1.0
elif front_ttc < 1.0:
    lane_escape = close_rear
    target_speed_factor = 0.5
elif front_ttc < 3.0:
    target_speed_factor = 0.7
elif fire:
    target_speed_factor = 0.8
else:
    target_speed_factor = 1.0
```

这里的出发点是：传统 TTC 或 RSS 类方法在前方冲突时容易硬刹，在后车压力场景中会把前向碰撞风险转化为后向追尾或重叠碰撞。RearEscape 不把后方威胁简单等价为“刹车更强”，而是在前向 TTC 尚未低于 1s 且后车距离/后向 TTC 危险时保持速度并给出 `lane_escape=1`，让 SUMO 闭环控制中的路点/车道意图映射有机会向安全侧逃逸。

## 10. 公平性与仍存在的问题

1. DeepAccident 是离线 GT/perception 评测，不能直接模拟 ego 控制后的真实碰撞；所以 DeepAccident 的 `CollRate` 只是数据集事故标签比例。
2. DeepAccident 的 FA(s) 对几何修正方法偏严：只要正常场景任一帧有修正就计为场景级 FA，因此 Hybrid 系列 FA(s)=100%。更适合横向比较的是 FA(f)、WPC 和 Mod。
3. SUMO 中 `OverlapRate` 和 `CollRate` 不完全等价；有些 overlap 来自重叠事件统计，而 `CollRate` 是 `unique_ego_coll > 0`。最终判断同时列出两者。
4. FullSafety 已接入同评测，但完整主表默认不包含它，原因是速度慢且 smoke 结果差。若论文要强调 RiskMap/RiskGraph/RiskEvent 三层框架，需要继续优化 `SafetyConstraintModule` 并跑完整表。
5. 随机压力集目前只有 seed=42。它证明随机复杂场景管线可跑通，但不能代表大规模统计结论。后续建议扩展到至少 5-10 个 seeds，并把每个 seed 的 route 文件参数写入 metadata。
6. 当前最终方法中的 `lane_escape` 依赖 SUMO 闭环控制对 stats 的解释；DeepAccident 离线评测只能验证路点碰撞和检测指标，不能完全验证横向逃逸动作。
